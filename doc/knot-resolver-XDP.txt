═══════════════════════════════════════════════════════════════════════════════════════
                    WHY BOTH XDP PROGRAMS ARE MUTUALLY EXCLUSIVE
═══════════════════════════════════════════════════════════════════════════════════════

    ┌─────────────────────────────────────────────────────────────────────────────────┐
    │  Reason 1: XDP_REDIRECT bypass                                                 │
    │  ───────────────────────────────────────────────────────────────────────────── │
    │  xdp_dns_denylist uses XDP_REDIRECT which sends packets directly to the       │
    │  socket, bypassing ALL subsequent XDP programs on the same interface.         │
    │                                                                                 │
    │  Result: When xdp_dns_denylist runs, dns_fw receives ZERO packets.             │
    └─────────────────────────────────────────────────────────────────────────────────┘

    ┌─────────────────────────────────────────────────────────────────────────────────┐
    │  Reason 2: Wildcard vs. Exact Match                                            │
    │  ───────────────────────────────────────────────────────────────────────────── │
    │  xdp_dns_denylist: ✅ Supports wildcard domains (e.g., *.example.com)          │
    │  dns_fw:           ❌ Only supports full qualified domain names (exact match)  │
    │                                                                                 │
    │  Result: xdp_dns_denylist is MORE CAPABLE, so we use it when XDP=off.          │
    │          dns_fw is used when we want XDP acceleration (but lose wildcards).    │
    └─────────────────────────────────────────────────────────────────────────────────┘
